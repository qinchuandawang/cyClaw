# cyClaw 产品定位说明 v0.4

日期：2026-07-19

## 1. 核心定位

cyClaw 是：

> 面向 Coding Agent 与开发团队的独立项目知识观察器与治理器。

它不依赖 Codex 调用 MCP、填写任务或主动上报执行结果。它在旁路持续采集可验证项目事件：

- 文件系统与 Git 变化。
- 测试和构建报告。
- 事实证据内容漂移。
- 知识重复、冲突、失效和取代关系。

一句话描述：

> 在不打断 Coding Agent 的前提下，持续把项目变化变成有证据、可治理的长期知识。

## 2. 为什么不是普通文档助手

Codex 已经能够主动新增或更新文档，因此“检测代码变化并提醒写文档”不足以形成独立价值。

cyClaw 处理的是模型本身难以长期负责的问题：

- 跨会话长期记忆。
- 不同 Agent 之间的项目事实一致性。
- 代码、文档和历史决策之间的冲突。
- 旧知识的失效、取代和删除。
- 重复文档和持续追加造成的知识熵增。
- 为当前任务编译最小有效上下文。

Codex 优化当前任务，cyClaw 优化项目整个生命周期中的知识质量。

## 3. 与 RAG 的关系

RAG 是 cyClaw 的读取路径，但不是完整产品。

```text
普通 RAG：问题 -> 相似片段 -> Prompt -> 回答

cyClaw：任务开始 -> 上下文编译 -> Agent 执行
      -> 事实捕获 -> 冲突与重复检查 -> 知识治理
      -> 下一次任务继续使用
```

cyClaw 可以理解为：

```text
Agentic RAG
+ Project Memory
+ Temporal Knowledge
+ Context Compiler
+ Knowledge Governance
```

## 4. 五种知识治理操作

文档和知识资产不能只有 append。cyClaw 将以下操作作为一等能力：

| 操作 | 含义 | 使用场景 |
| --- | --- | --- |
| `create` | 新增不存在的知识 | 没有任何现有章节覆盖该事实 |
| `update` | 修改现有章节 | 事实仍有效，但内容需要同步代码变化 |
| `merge` | 合并重复章节 | 多处记录同一约束或说明 |
| `supersede` | 保留历史并声明被新事实取代 | 架构决策、兼容策略、业务规则发生替换 |
| `delete` | 删除章节或整份文档 | 内容已失效且继续保留会误导 Agent |

默认决策顺序：

```text
检索已有知识
-> 是否重复：merge
-> 是否仍有效但过期：update
-> 是否需要保留历史：supersede
-> 是否已经无效且有害：delete
-> 确认没有现有知识：create
```

重点不是生成更多文档，而是减少文档熵增。

## 5. 项目记忆模型

cyClaw 需要维护四类记忆：

| 记忆 | 内容 |
| --- | --- |
| 事实记忆 | 当前系统行为、API、Schema、约束和环境要求 |
| 决策记忆 | 为什么采用某个架构或实现方案 |
| 失败记忆 | 尝试过但不可行的方案及原因 |
| 任务记忆 | 一次 Agent 任务的目标、上下文、过程、结果和后续事项 |

每条长期知识应逐步包含：

```text
声明
类型
证据路径
来源任务
置信度
有效状态
生效版本
取代关系
最后验证时间
```

## 6. 上下文编译

任务开始时，cyClaw 不应把整个仓库或整个知识库交给 Codex，而应生成任务相关上下文包：

```text
任务目标
相关代码与文档
现有业务约束
历史架构决策
失败过的方案
兼容性限制
相关测试
未完成事项
```

上下文包必须：

- 有来源。
- 有优先级。
- 有 Token 上限。
- 排除重复和失效知识。
- 能说明为什么某条知识与当前任务相关。

## 7. 自主观察闭环

目标流程：

```text
独立 Observer 启动补偿
-> 文件/Git/报告事件
-> 证据化、去重和影响分析
-> 候选知识
-> 事实证据验证与项目对账
-> 可审计 Patch
-> 人工审批或确定性治理动作
```

当前已完成的基础：

- Git 和文件事件变化检测。
- 候选知识与证据。
- 本地索引和 MCP 检索。
- 文档 Patch、Diff、应用和撤销。
- `create/update/merge/supersede/delete` 五种治理操作。
- 权限、置信度、模型审查和事件审计。
- Codex stdio MCP、Skills、Session Hook 和 Git Hook。

任务记忆和上下文编译仅作为兼容读取接口；下一阶段重点是扩展独立事件源、事件账本恢复和确定性知识治理。

## 8. 与 Codex 的边界

```text
Codex：
- 理解和修改代码
- 完成当前开发任务
- 推理、规划和工具调用

cyClaw：
- 保存项目长期记忆
- 编译任务上下文
- 维护事实与代码一致性
- 管理知识的更新、合并、取代和失效
- 连接不同会话和不同 Agent
```

cyClaw 不复制 Codex 的编码能力，也不尝试成为第二个通用 Coding Agent。

## 9. 产品指标

不以生成文档数量衡量价值，重点指标是：

- 新会话恢复项目上下文所需时间。
- Codex 重复探索同一问题的次数。
- 历史错误和失败方案再次出现的次数。
- 发现的代码与知识冲突数量。
- 合并或删除的重复、过期文档数量。
- 注入模型的上下文 Token 与有效信息比例。
- 高价值知识在任务结束后的留存率。

## 10. 当前阶段结论

cyClaw 的核心不再是：

> 代码变化后自动追加一段文档。

而是：

> 在 Coding Agent 工作前提供正确上下文，工作后治理项目记忆，并让知识能够被更新、合并、取代和删除。
